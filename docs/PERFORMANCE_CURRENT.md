# 2026-11-03 · 高怪量性能检查

本轮在独立本地浏览器页检查 230 个高生命敌人和 8 件进化武器，没有修改用户正在玩的对局。怪物数量、伤害、弹体和攻击机制没有因性能检查削减。

## 热点与局限

第一轮 6.54 秒实际主循环采样：225 次渲染，约 34.4 帧/秒；画布约 144 万像素、DPR 1.25。带函数计时包装的 `render` 平均 7.70 ms，其中 `renderActor` 约 3.46 ms；`update` 平均 1.55 ms，`stepProjectiles` 约 0.066 ms。该场景优先检查角色绘制；函数计时本身有开销，数据不是所有设备的通用结论。

## 被排除的阴影缓存方案

尝试把角色阴影的斜投影预先栅格化，以减少逐帧变换。静态角色绘制曾有较低的主线程工作时间；但修正实验脚本、确保每帧确实执行战斗更新后，动态 A/B 没有支持保留它。

固定种子、初始 230 敌人（事件触发后 236）、八件进化武器、DPR 1.25，预热 60 帧后交替测量，每组 180 帧：

| 顺序 | 原有投影/实验缓存 | 平均工作耗时 | P95 工作耗时 | P95 帧间隔 |
| --- | --- | --- | --- | --- |
| 1 | 原有投影 | 7.97 ms | 10.70 ms | 33.90 ms |
| 2 | 实验缓存 | 8.57 ms | 11.90 ms | 33.90 ms |
| 3 | 实验缓存 | 8.34 ms | 11.50 ms | 33.50 ms |
| 4 | 原有投影 | 7.70 ms | 10.20 ms | 33.40 ms |

实验缓存使本次动态场景主线程工作时间增加，且没有稳定帧间隔收益，已从运行时代码撤回。原始结果在 `qa/performance-actor-cache.json`。`scripts/browser-actor-benchmark.js` 保留实验实现以供复现，仅可在独立 QA 页手动执行，不随游戏加载。

早期脚本把 `state` 留在 `qa`，导致 `update()` 直接返回，因此那轮结果只能表示静态绘制，不能作为动态战斗性能证据；上表及 JSON 已使用修正后的动态流程。

## 最终保留的变更

仅保留 `actorPoseKinds`：按敌人类型缓存飞行/软体/普通类别，避免每个角色每帧重复创建两组数组与执行子串分类。不改变姿态公式、阴影绘制、敌人数量或伤害。`scripts/test-actor-cache.cjs` 验证分类与原规则一致，`scripts/test-immersion.cjs` 通过。

本轮不能宣称卡顿已根治，也没有证明稳定帧率提升。短时同机、多预览页和浏览器栅格化负载都会影响帧间隔。已有 `scripts/performance-benchmark.cjs` 的旧模块清单缺少 `MORE_WEAPONS`，当前会报错，不能将其旧结果当作本轮验收。后续若增加景深，优先复用离线柔焦缓存，避免逐帧全屏滤镜。


主流程另调整渲染分辨率反馈：当平滑帧间隔超过 22ms 时，不再额外要求主线程工作超过 7ms，因而 GPU/合成慢帧也可以触发降分辨率；恢复条件收紧至帧间隔小于 17.5ms、主线程工作小于 5ms。保持原有 180 帧检查周期和 1–1.5 范围，不改变模拟、敌人数和伤害。本项未单独取得可归因的跨设备 FPS 改善数据。
